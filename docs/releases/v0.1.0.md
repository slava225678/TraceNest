# TraceNest Lite v0.1.0

Initial release of a local Python error tracker with an installable SDK,
error grouping, and a web interface. Capture exceptions from an application,
store individual occurrences in PostgreSQL, and inspect recurring errors
and their tracebacks in the browser.

## Included

- FastAPI endpoints to submit, list, and retrieve events, with validation,
  pagination, request size limits, and API key protection for writes.
- Python 3.12+ SDK (`tracenest-sdk` 0.1.0) with synchronous exception capture,
  bounded payloads, and safe delivery diagnostics.
- Error grouping by application, exception type, and Python stack frames,
  with occurrence counts, first/last timestamps, and event history.
- Resolve/reopen actions through the API and UI. A new occurrence reopens
  a resolved group.
- Jinja2 web interface with application/status filters, pagination,
  individual tracebacks, and a responsive layout.
- Alembic migrations that preserve events from earlier development stages
  and backfill their groups.
- Docker Compose setup, PostgreSQL integration tests, Ruff linting, and
  GitHub Actions checks that also build the SDK wheel and source archive.
- English documentation, screenshots, and an MIT license.

## Try it locally

From the repository root with Docker Desktop running (Git Bash):

```bash
# First launch only; preserve an existing .env.
cp .env.example .env
docker compose up --build -d
curl -sS http://127.0.0.1:8000/health
```

Open <http://127.0.0.1:8000/> for the dashboard or
<http://127.0.0.1:8000/docs> for the API documentation.
See the repository README for SDK installation and an exception example.

## Upgrade from a development version

Keep your existing `.env` and database volume, then rebuild the API:

```bash
docker compose up --build -d api
```

Startup applies migrations automatically. Existing event IDs, payloads,
and timestamps are preserved. Back up existing data before upgrading;
group backfilling locks the event table. Do not remove the database volume
with `docker compose down -v`. Destructive downgrades are unsupported.

## Known limitations

- Intended for local development. Read endpoints and the UI have no user
  authentication; Compose binds the API to `127.0.0.1`.
- SDK delivery is synchronous, with no retries, queue, or delivery guarantee.
- Grouping uses filename basenames and function names. Similar stacks can
  merge; changed stacks can split. Unparsed traces use the exact message.
- Tracebacks and messages may contain sensitive application information.
  Automatic data redaction, retention policies, and rate limiting are absent.
- The UI requires a refresh to show new events. Status changes require
  JavaScript or a direct API request.
- SDK installation is from source or a locally built archive. CI does not
  publish to PyPI, create GitHub releases, or deploy the service.
